## What to build (server side, TypeScript — all in apps/server)

### 1. Jev decision service: `apps/server/src/services/jev.ts`
Port the pattern from anyfilter (Chrome extension using Jev, reference code at /tmp/anyfilter — READ IT, especially src/infrastructure/jev/jev-payload.ts, src/infrastructure/classifier.ts, src/infrastructure/jev/typesafe-direct-adapter.ts, src/infrastructure/jev/vercel-gateway-adapter.ts).

Jev API (TypeSafe direct): `POST https://api.typesafe.ai/v1/systemone`
Body shape: `{ model: "jev-latest", state: {...}, questions: { <id>: { type: "choice"|"score"|"noul", instructions, criteria } } }`
- `questions` is a RECORD (object), not an array.
- For `choice` type: criteria is a MAP `{ "<optionLabel>": "<criteria text>" }` (NOT `options`).
- For `score` type: criteria is an ordered ARRAY.
- Question IDs are never sent to the model.
- Response: `{ answers: { <id>: { choice|probability, ... } }, usage: {...} }`.

Implement `classifyRequest(userId, latestUserText)` returning a typed decision:
```ts
type ChatIntent = {
  useAppTools: boolean;          // replaces regex shouldUseAppIntegrationTools
  toolkits: string[];            // replaces regex appToolkitsMentionedInRequest
  isAnalystQuestion: boolean;   // analyst mode: analysis/explanation of screen content
  answerVerbosity: "brief" | "normal" | "deep";
  gate: "allow" | "block";       // content gate (spam/NSFW/unsafe instructions)
};
```
Questions (all in ONE systemone call, they run in parallel):
- `appTools`: choice — options: yes/no. Criteria: yes = user asks to create/edit/search/send/schedule/organize content in an external connected app (notion, gmail, slack, github, docs, sheets...); no = screen pointing/navigation/visual questions or general chat.
- `toolkits`: choice — one option per supported toolkit (notion, googlecalendar, googledocs, googledrive, googlesheets, googleslides) with criteria mapping mentions → toolkit.
- `analyst`: choice — yes = the user asks to analyze, interpret, evaluate, compare, summarize, extract insights, review figures/tables/data/code visible on screen; no = simple lookup or navigation.
- `verbosity`: choice — brief/normal/deep per criteria.
- `safety`: choice — allow/block: block if request is spam, NSFW, hateful, or asks to perform clearly unsafe actions.

Handle failures by FAILING OPEN (default: useAppTools=false, toolkits=[], analyst per current regex fallback in instructions.ts, gate=allow) with a short 2s timeout — never break chat on Jev errors, and log the fallback.

Graceful: if env `JEV_API_KEY` (or `TYPESAFE_API_KEY`) is absent, skip the call entirely and use the existing regex functions.

### 2. Wire into `apps/server/src/routes/chat.ts`
Call the Jev service before building the stream; use its decision instead of the two regex functions. Pass `isAnalystQuestion` + `verbosity` into a new system-prompt extension `withAnalystInstructions(...)` in instructions.ts that, when analyst mode is on, appends analyst instructions:
- Structure answers: direct answer first, then key evidence from the screen, then implications/recommendations.
- Quote concrete numbers, labels, code identifiers from the visible content.
- Prefer deep multi-angle analysis when the question warrants it.
- Keep it speakable (it will be read aloud).
When gate=block, return 400 JSON `{ error: "blocked" }` without calling the model.
